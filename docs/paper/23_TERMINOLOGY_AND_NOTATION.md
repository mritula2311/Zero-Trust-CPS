# Terminology and notation

| Term / symbol | Canonical meaning |
|---|---|
| Security Trust, S_sec | Trust-style cyber-behaviour score of an authenticated device; high is good |
| Process Trust, S_proc | Fused process normality probability; high is good |
| Process Anomaly Score | Legacy name for high-is-normal process output; explicitly state polarity |
| Anomaly probability, a |1−normality probability when that conversion is used |
| Local detector | Rule/IF/sequence model using the target's physical reading/history |
| Relational score, r_i | Per-target normality computed from network local-score context |
| Physical node / REAL_HARDWARE | Identity with evidence from a physical sensing device |
| LEGACY_SIMULATED | Parametric simulator output; not generated by the real-derived virtual method |
| REAL_DERIVED_VIRTUAL | Transformed empirical source trajectory with synthetic perturbations |
| HYBRID | Dataset/network combining physical-source and generated identities |
| Pending node, valid_i=False | Declared slot with no measured observation in this split; excluded before model arithmetic and metrics |
| Isolated anomaly | Constructed anomaly affecting a single target in a scenario/event definition |
| Coordinated anomaly | Constructed event affecting multiple related network targets; exact scenario definition must accompany result |
| Mixed cardinality, n | One model exposed to different sampled node counts |
| Mixed provenance | Training pool combines legacy hybrid and real-derived virtual sources |
| Topology intervention, A | Controlled adjacency change with stated other variables held fixed |
| Permutation equivariance | `f(PX,PAP^T)=P f(X,A)` for graph relabelling, or `f(PX)=P f(X)` for node-output sets |
| Permutation invariance | Output unchanged under input permutation; appropriate for pooled set context |
| Contextual bandit | Reward-based action-value estimation for a context without sequential Bellman learning |
| Zero-Trust policy | Explicit decision over separate trust evidence, plus authenticated operational overrides |
| ALLOW / ALERT | Permit normal traffic / preserve telemetry and flag physical concern |
| STEP_UP / BLOCK | Request extra proof / deny under combined or overriding concern |
| REJECTED | Pre-policy authentication/validation outcome, not a fifth PDP class |
| θ | Threshold selected using the stated validation protocol |
| N vs n | Declared network cardinality versus actual valid/tested subset; always label the distinction |
| TP/FP/TN/FN | Confusion counts whose positive class is explicitly named |
| FPR | False positives divided by true-normal support for anomaly detection |
| CI | Interval whose sample unit and construction must be stated |

Status tags: [VERIFIED] evidence checked; [CURRENT] authoritative for its stated protocol; [DEPLOYMENT / LIVE] only for a directly observed deployment; [DEPLOYMENT CANDIDATE] serving implementation available; [EXPERIMENTAL] research-only; [HISTORICAL]/[SUPERSEDED] preserved chronology; [REJECTED / ABLATION-ONLY] no supported deployment benefit; [PENDING VALIDATION]/[REQUIRES RERUN] missing experiment; [UNRESOLVED — DO NOT USE AS FINAL PAPER CLAIM]/[UNKNOWN] evidence insufficient.

Avoid “full RL” (use contextual bandit), “20 physical nodes” (use20-node constructed benchmark), “two MPU6050s” (name both modalities), “GNN embeddings” for the Task2 scalar-score vector, “peak” without the peak-to-peak definition, and “final deployed M6” before fusion integration. These corrections preserve original source identifiers where renaming would break reproducibility.
